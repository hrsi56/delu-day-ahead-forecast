**How to use it.** Read `progress.md` → find the row after the last completed stage → read **only** the sources that row's *Briefing sources* column names. That is the read; you do not re-read the anchor end-to-end to write a routine brief.

**Constant briefing inputs (stated once — every row inherits these by executor):**

- **NotebookLM rows:** prompt fields per ORC §"Type L"; teaching style, floor calibration, and the checkpoint consolidation verdict per the NotebookLM role doc; depth label from the cited source row. The L block sets the ceiling only.
- **Engineering-Lead rows:** brief fields per ORC §"Type B-Claude"; workflow per that repo's `engineering-role.md`. A code-authoring brief names exactly one repo/checkpoint, the exact ratified anchor, the complete named CP/FCP checklist plus a supporting extract, and one numeric active-elapsed wall-clock ceiling covering orientation through terminal return. The cited plan owns architecture and acceptance; the Lead owns decomposition and internal routing. Parallel agents never create additive elapsed time. Yarden carries one brief in and one consolidated Return Packet out. No `PASS` starts the next row. FM rows point at the **fraud repo's own** `engineering-role.md` + FRD once that repo exists (FM0 creates it).

- **Claude-chat rows:** fields per ORC §"Type C-Claude". **Research-agent rows:** fields per ORC §"Type C-Research" / §"Type B-Research". Positioning theme + CV cadence from PRG Track C.
