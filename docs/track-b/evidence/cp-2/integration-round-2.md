## Observations (non-blocking; no checklist item turns on them)

1. **`holdout_report.json: completed_runs_recorded = 1` understates reality.** It is a local counter (`previous.get(…, 0) + 1 if previous else 1`) that resets whenever the prior report lacked the key, while MLflow records nine completed champion runs. The field is not load-bearing and the adjacent `execution_note` pre-empts it in terms — it states the script "was run repeatedly", that every completed run reproduced the previous run's metrics and fingerprint exactly (which I confirmed: one metric set, one fingerprint across all nine), and that "the authoritative run count is the public MLflow record, not a number written here." The note therefore makes no numeric claim it cannot support; the counter is simply weaker than the note that governs it.
2. **README ordering.** `docs/cp2-model-report.md` places the two pooled losses and the percentage difference under an explicit "The numbers, before the conclusion:" heading ahead of the selection. The README leads with the bolded "**Selected catalog: `base`**" and gives both unrounded losses and the exact percentage difference in the immediately following clause. Plan §4.1 and bar item 3 require that the losses, the difference and the selection be *reported*, not that they be ordered, and the outcome reported is the unfavourable one, so nothing is buried or spun — but the README does not mirror the report's stricter numbers-first arrangement.
