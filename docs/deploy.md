# Deployment — owner-only

Nothing an agent runs publishes anything. Every step that changes a public surface below is the
Owner's (AGENTS.md § Git and publication authority); an agent prepares, checks and hands over.

| Surface | Source in this repository | How it is published |
|---|---|---|
| Report, [GitHub Pages](https://hrsi56.github.io/delu-day-ahead-forecast/) | `docs/index.html`, generated by `scripts/build_pages.py` | A push of `main`; Pages serves `docs/` |

The Space is a **Static** Space: the champion's nine boosters run in the visitor's browser under
Pyodide, and nothing executes on Hugging Face's side, so there is no process to sleep or wake. The
report is one self-contained file; after it loads it makes no further requests.

## The order of a publication

PUBLISH_RULES 1.0 §11 fixes it: build from the packet; editorial review; the fresh reader; the
independent check; the MLflow upload and its verification, only when the committed export changed;
the final build; a focused recheck on the final candidate; then the Owner's landing, push and Space
upload; then the public post-deployment checks. The runbook
(`docs/track-b/publication-runbook.md`) names every touchpoint.

## Build the demo bundle

```bash
make wasm
```

That regenerates the browser payload from the committed champion, proves it bitwise equal to the
frozen artifact on the committed fixture, exports the notebook with `marimo export html-wasm` and
assembles `dist/space-wasm/`: `index.html` with its static loading, failure and retry states and the
control-name repair, marimo's `assets/`, `public/` (the nine boosters as base64-encoded gzip text, the
row slice, the fixture and `browser_champion.py`), the card as `README.md` with `sdk: static`, and
`.gitattributes` routing binary assets through LFS. It exits non-zero if the bundle is malformed, if the
shipped module differs from the verified one, or if an internal file leaked into it.

To see it before uploading, serve it over HTTP (`file://` cannot run a WASM notebook), then open
<http://127.0.0.1:8820>:

```bash
make wasm-serve
```

## Upload the reviewed bundle — the Owner

The review binds a bundle hash. First check that the bundle is that one and that no local credential
value is in any of its files; this reads no secret for use and changes nothing:

```bash
uv run python scripts/deploy_space.py --bundle dist/space-wasm --expect <reviewed bundle sha256>
```

Then upload it:

```bash
uv run --with huggingface_hub python scripts/deploy_space.py --bundle dist/space-wasm --expect <reviewed bundle sha256> --upload --record reports/presentation/release-checks/<date>-space-deployment.json
```

The script repeats both checks, confirms the Space is public and Static, and uploads exactly those
files with `HfApi.upload_folder` against the revision it has just read, so a concurrent change fails
instead of being overwritten. It then compares every remote file with the bundle (the Git blob
SHA-1, or the SHA-256 of a file stored through LFS) and writes the record. `HF_TOKEN` is read inside
the process and is never printed, logged or written; `huggingface_hub` is supplied for that one run
and `uv.lock` is untouched. A remote file the bundle does not carry, such as the Space template's
unused `style.css`, is left in place and listed in the record. This is the operation PRES-1 used on
2026-09-29.

## After a publication: the public checks

PUBLISH_RULES 1.0 A6 asks, per surface, for the URL, the UTC time, the served revision and bytes, the
behaviour observed, and every first failure and retry. The checks run against the public addresses:

```bash
.local/tools/playwright/bin/python scripts/check_reader_paths.py release https://hrsi56.github.io/delu-day-ahead-forecast/ --shots .local/artifacts/<task>/public-report --out reports/presentation/release-checks/<task>-public-report.json
```

```bash
.local/tools/playwright/bin/python scripts/check_reader_paths.py demo --engine chrome --engine webkit --viewport 1440x900 --viewport 390x844 --out reports/presentation/release-checks/<task>-public-demo.json
```

```bash
.local/tools/playwright/bin/python scripts/check_reader_paths.py demo-a11y --engine chrome --engine webkit --viewport 1440x900 --viewport 390x844 --out reports/presentation/release-checks/<task>-public-demo-a11y.json
```

```bash
uv run python scripts/verify_mlflow_mirror.py verify --target public --out reports/presentation/release-checks/<task>-public-mirror.json
```

```bash
uv run python scripts/check_links.py
```

A new record gets a new name; a first failure stays in its record beside any retry.

## The container — local evidence, not hosted

`make container-verify` builds the Docker image and runs it with the network disabled, recording the
run in `reports/cp3/container_check.json`. Hugging Face moved its Docker and Gradio SDKs behind a paid
plan on 2026-07-08, so the container is not hosted; the Static Space above is the demo. The archived
v1 report's container instructions describe that path as it was published on 2026-09-15.

## Link discipline

Link experiment tracking **only** through <https://dagshub.com/hrsi56/delu-day-ahead-forecast.mlflow>.
The DagsHub repository root, `/experiments`, `/models` and `/src/main` redirect an anonymous visitor to
a sign-in page. `make verify` fails if one appears on any surface in this repository; it cannot see a
CV or a LinkedIn profile.
